# JobIntel AI — локальный минимум

Один процесс FastAPI, одна локальная SQLite, одна страница. Вставьте текст вакансии и сведения кандидата, получите сравнение с проверяемыми цитатами, сохраните и выгрузите JSON. URL служит только ссылкой для человека; приложение его не загружает. Доступ — только `127.0.0.1`, без авторизации.

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
export JOBINTEL_OPENAI_API_KEY='...'  # только если вы разрешаете отправить оба текста провайдеру
make run
# открыть http://127.0.0.1:8000/
```

Ключ передаётся только через переменную окружения, не сохраняется. `JOBINTEL_OPENAI_MODEL` выбирает модель (по умолчанию `gpt-4o-mini`). Реальный вызов расходует средства аккаунта и передаёт оба текста OpenAI; запуск UI или тестов сам его не выполняет. Без ключа сравнение возвращает явную ошибку. БД по умолчанию `local_data/jobintel.sqlite3`, путь задаётся `JOBINTEL_DB`. Скопируйте файл для резервной копии; остановите сервер перед копированием. `make check` и `make build` проверяют код и сборку.

Модель возвращает 1–20 требований. Сервис проверяет точное вхождение каждой цитаты и вычисляет Unicode offsets, но не способен автоматически доказать смысловую корректность вывода модели. `SUPPORTED` означает утверждение модели с цитатой; `UNKNOWN` — недостаток сведений. Просматривайте каждое утверждение. Данные и результаты сохраняются неизменяемыми записями; повтор того же UUID idempotency key возвращает запись без нового вызова. После аварии операция остаётся неопределённой и повтор с тем же ключом запрещён, чтобы не отправить данные повторно. Проверьте историю, прежде чем начать новую операцию.

## Старые данные и откат

Не запускайте импорт поверх оригинала. Сохраните резервную копию старой SQLite и выполните:

```bash
.venv/bin/python -m jobintel.import_legacy old.sqlite local_data/jobintel.sqlite3
```

Импорт читает исходную БД в режиме `mode=ro`, копирует все строки всех таблиц в `legacy_archive` с SHA-256 исходного файла и создаёт пары snapshot/candidate только для сохранённых match runs как исходные записи **без результатов inference**. Повторный импорт идемпотентен. Для больших баз используйте отдельную копию и проверьте объём до импорта. Несвязанные snapshots и candidate revisions остаются в архиве без выдуманной пары. PostgreSQL автоматически не мигрируется: сделайте SQLite экспорт из прежней версии или сохраните прежний сервер для доступа к истории. Исходные миграции и код остаются в Git истории на `main`; откат — переключить ветку и использовать неизменённую прежнюю БД. Старые результаты в `legacy_archive` не пересчитываются и не выдаются за новые.

[Новая карта приёмки и отложенных задач](docs/scope.md).

Опциональная проверка браузера: установите `playwright` и Chromium отдельно (`JOBINTEL_CHROMIUM` задаёт путь к браузеру) и запустите `.venv/bin/python tests/browser_check.py`. Она использует временную БД и проверяет desktop/mobile, переполнение и безопасное отображение HTML.
